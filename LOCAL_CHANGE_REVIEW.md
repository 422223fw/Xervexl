# Review of existing local changes — 1 November 2026

This separates inherited working-tree changes and local drafts from the skin,
cape, rank-technique and Windows-status implementation. Uncommitted files do not
identify their author; this report does not attribute them to a person. Existing
drafts were inspected as data, not executed as instructions.

| Existing change | Observed effect | Handling |
| --- | --- | --- |
| `src/controls.hpp`: expanded control mapping, named thresholds, `AttackType`, guard logic and assertions | The inherited edit lacked the closing structure delimiter, printed debug output on the input path and could request attacks just from walking. Its block return and diagonal tie rule differed from the authoritative controls. These could prevent a build or change unintended combat behaviour. | Kept the expanded structure; repaired the delimiter, removed the print, restored attack-button gating, empty attack during block and consistent diagonal selection. Native control checks pass. These repairs are included in the feature commit. |
| `bot_learning.py`: eager compatibility import of `BotBrain` seen in the initial working tree | `bot_brain.py` already imports learning definitions, so the eager reverse import created a circular import and prevented server startup. | Replaced it with a lazy compatibility export. Production learning data was retained. This repair is included in the feature commit. |
| `tests/test_animation.py`: three additional regression checks | Checks foot-step output at extreme speed, gait periodicity and body shapes while blocking. These tests passed within the 257-test maintained run. They affect tests, not gameplay. | Left the existing local edit untouched and unstaged. |
| `bot_brain_improved.py` | A separate, partial `BotBrain` example containing a target-selection method. The production server imports `bot_brain.py`, not this file, so it does not improve the live bots. | Left local and excluded from the release archive. |
| `src/game_modes.py` | Contains only an `os.getcwd()` print. Actual game modes are implemented in root `game_modes.py`; this draft adds no mode. | Left local and excluded from the release archive. |
| `arena.vert` in the repository root | A separate shader draft. The game build uses `shaders/arena.vert.spv` generated by the maintained shader tools; this root file is not selected by the build. | Left local and excluded from the release archive. |
| `tests/test_bot_bias.py` | Calls `BotBrain.observe()` and `BotBrain.values`, which the tactical mixin does not provide. It fails if selected as a test. Fixing the compatibility import does not add that unavailable API. | Left local; excluded from the maintained test run and release archive. |
| `Xervexl_combat_replay_scenario.py`, `tests/combat_replay_test.py` | Both contain invalid Python placeholders such as `setup_game_state...` and import unavailable `xervexl_gameplay`. They are not usable replay tests and fail collection/compilation. They do not run as part of the server. | Left local and excluded from the maintained run and release archive. Syntax was checked without executing them. |
| `rename_file.py` | Contains an invalid Python Windows path escape, so it cannot run as written. Its stated action would rename the production `bot_brain.py` without updating imports, which would break startup. | Inspected only; never executed or included in the release. |
| `verify_thresholds.py` | Tries to import `controls` as a Python module. Control logic is a C++ header, so this script cannot verify it in the present project. | Left local; the actual native control check was used instead. |
| `run_tests.py`, `tests/test_capacity_unittest.py` | Unittest runners without test cases. Their success alone would not establish game correctness or 100-player capacity. | Left local; not counted as successful regression tests. |
| Root `test_bot_bias.py` | An 18-byte comment stub, distinct from the failing test under `tests/`. | Left local; it adds no test coverage. |
| `validate_assets.py` | Standalone asset-header/JSON inspection. It is not imported by the game and does not alter assets. | Inspected only; left local. |
| `Xervexl/combat_improvements.md`, reports, package instructions, result markers, `junit.xml` and `build_output.txt` | Notes or recorded results. Their contents do not themselves apply code, rebuild the executable or prove that current tests passed. | Left local and excluded from the public package. |

An unrelated application, FRREUT, was also found listening on the default local
port 8765. This is a machine-state conflict, not an Xervexl source change. The
launcher now reuses a matching Xervexl server or selects another local port,
without stopping the other application. The running game was first opened on
8766 before any new Git commit, as requested.

The maintained test runner selects tracked regression tests plus the new feature
tests. Its 257 passing tests do **not** mean every local draft passes discovery.
Private accounts, remembered-login grants, saves and learned bot state are never
included in Git or the portable archive.
