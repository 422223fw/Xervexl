# Validation — Xervexl 0.5, 14 October 2026

- **97 regression and integration tests passed** on the final server. New checks cover real hit/miss learning, an overhead-counter opponent changing the bot's subsequent forecast choice, actual guard outcomes, damage/death costs, idle-guard reward prevention, entry-grace/world isolation, delayed shot credit, reflection/expiry, shutdown interruption, magic ward attribution, continued adaptation, bounded storage, atomic checkpoint retries, corruption recovery and exact reload of learned memory.
- Easy mode is now the default: hold left click for alternating cuts, release to cancel automatic follow-ups, right click to block/cancel, middle click for thrust and V for overhead. The authoritative server retains recovery, stamina costs and facing checks. Guard assistance observes nearby shown windups only; holding it does not refresh perfect-parry timing. Regression checks verify repeat/cancel behaviour and the preserved manual mode.
- The native C++ game compiled successfully with the installed portable compiler. A separate C++ controls check verified movement-independent easy cuts, all directional selections, thrust/overhead shortcuts and block priority. Native UI automation against isolated accounts verified registration/login, huge-XP rendering, inventory, logout, both saved control settings, **2 humans + 8 bots**, and OpenGL-to-Vulkan switching with the same fighter.
- A fresh deterministic 30-second self-play run produced **215 attacks, 16 eliminations, 1,209 learned action samples and 358 contexts** in 1.67 seconds of wall time. Reloading its separate server restored the exact learning table. This is an activity/persistence check, not a human difficulty benchmark or proof of monotonic improvement.
- Online contextual action values are confidence-weighted corrections to the existing bounded 2–5-step forecast, with small exploration among nearby choices. Bot health, damage, rank rules and reaction delays are not increased by learning. Aggregate memory is private, bounded to 4,096 contexts and excludes player identifiers. It checkpoints every five server seconds and at clean shutdown; abrupt termination can discard the latest uncheckpointed updates.
- Runtime accounts, learned memory, control settings, synthetic fixtures, screenshots and logs remain excluded from Git and the portable archive. Public hosting, SMTP delivery, prolonged operation, large populations and human balancing remain untested. Rendering and simplified collision retain the prototype limits in README.md.
- Activation verified the installed executable's SHA-256 against the tested candidate, privately backed up runtime data and confirmed the account JSON stayed byte-for-byte unchanged across restarting the local server at **0.5.0**. The real game is running in a window titled **Xervexl | motlon**. A live health/file check confirmed continuing combat learning, successful checkpoints and more than 19,000 accumulated action samples without any human session. No administrator privileges were used.
